# 契約電子サイン E2E検証チェックリスト（ローカル）

本ブランチで実装した電子サイン機能を、ローカルの実DBで通し確認するための手順。
このコンテナではPostgres未接続のためE2Eは未実施です。以下をローカルで実施してください。

---

## 0. 事前準備（重要）

新しいPrismaモデルとフィールドをDBへ反映する必要があります。

```bash
# 依存とDB（ローカルのPostgres or Postgres.app 等）が起動している前提
npm install
npm run db:push        # SignatureField / SealStamp / sequential / signOrder 等を反映
npm run db:seed        # 初期データ（管理者 admin@guardsync.jp / GuardSync2026!）

# 開発サーバ（別ターミナル）: APIは3001、Viteは5173
npm run dev
```

- ログイン: `admin@guardsync.jp` / `GuardSync2026!`
- メール送信はSMTP未設定だと実送信されません。**署名URLはサーバのログ**（`/sign/<token>`）または開発時のメール出力で確認してください。SMTPを設定すれば実メールが飛びます。

## 1. PDFアップロード＋署名欄配置（作成）

- [ ] メニュー「電子契約」→「+ 契約書作成」
- [ ] タイトル・署名者（氏名＋メール）を入力
- [ ] 契約書PDFをアップロード → 「✓ Nページ」表示・プレビュー表示
- [ ] ツールバーで署名者と種別（署名/印影/日付/氏名）を選び、PDF上をクリックして欄を配置
- [ ] 配置した欄をドラッグで移動、×で削除できる
- [ ] 「作成して署名依頼を送信」→ 一覧に「署名依頼中」で表示

**期待**: 各署名者に少なくとも1つの署名/印影欄が必要（未配置だとエラー）。

## 2. 会社印の自動押印

- [ ] 作成画面でツール「会社印(自動)」を選択
- [ ] 「+ 画像登録(PNG/JPEG)」で角印画像を登録 → 一覧に表示・選択
- [ ] PDF上に会社印欄（グレー「会社印」）を配置（署名者不要）
- [ ] 作成後、締結完了時に署名済みPDFへ会社印が自動で焼き込まれている

## 3. 署名順序制御（sequential）

- [ ] 作成時「上から順番に署名を回す」をON（署名者に順序番号1,2…が付く）
- [ ] 作成直後は**先頭の署名者にのみ**依頼が送られる（ログのURLで確認）
- [ ] 2番目の署名URLに先にアクセスすると **403「順番待ち」** になる
- [ ] 先頭が署名完了すると、2番目へ依頼メールが自動送付される

## 4. 署名フロー（署名者側 / 未認証）

- [ ] `/sign/<token>` を開く → PDFプレビューと自分の署名欄がハイライト表示
- [ ] 署名欄タップ → 手書きサインを描画 → 確定 → 欄に反映
- [ ] 印影欄タップ → 手書き or 画像アップロード（PNG/JPEG）で押印
- [ ] 同意チェック → 「署名する（確定）」
- [ ] 全欄未記入だと確定ボタンが無効

## 5. 締結・成果物

- [ ] 全署名者完了で一覧が「締結完了」
- [ ] 詳細で **原本PDF / 署名済みPDF / 合意締結証明書** を表示できる
- [ ] 署名済みPDFに、配置した座標どおりに署名画像・日付・会社印が描画されている
- [ ] 詳細に「🕒 …時刻証跡」（サーバ発行タイムスタンプ）バッジが出る
- [ ] 合意締結証明書に署名者・日時・IP・SHA-256・タイムスタンプが記載
  - ※和文表示には `ESIGN_JP_FONT_PATH` にTTF（例: NotoSansJP）を指定。未指定時は英語ラベル

## 6. 期限・リマインド（cron）

cronは毎日AM8:00(JST)。即時確認したい場合は一時的にスケジュールを短くするか、
該当ロジックを手動実行して確認してください。

- [ ] 期限切れ（expiresAtを過去日で作成）→ cron後に「期限切れ」へ遷移
- [ ] 期限3日前以内 → 未署名者へリマインドメール

## 7. 取消・権限・分離

- [ ] 締結前の契約を「取消」できる（締結済みは不可）
- [ ] 一般ユーザー（非ADMIN/MANAGER）は作成・取消・会社印登録ができない
- [ ] 別会社のユーザーからは他社の電子契約/PDF/会社印が見えない（403/404）

---

## 改ざん検知の確認（任意）

- 署名済みPDFのSHA-256を再計算し、詳細に記録された値と一致することを確認。
- タイムスタンプ検証: `timestampToken = "srv:<ISO時刻>:<HMAC>"`。
  `HMAC-SHA256(署名済みハッシュ + "|" + ISO時刻, JWT_SECRET)` と一致すれば、
  その時刻にサーバがそのハッシュを確認したことの証跡になる（第三者TSAではない点に留意）。

## 既知の制約
- 署名済みPDFの日付/氏名/テキストはHelvetica描画のためASCIIのみ（日本語は署名画像で担保）。
- 会社印アップロードは会社横断の共有ディレクトリ（ファイル名=UUID）。厳密なテナント境界化は次段。
